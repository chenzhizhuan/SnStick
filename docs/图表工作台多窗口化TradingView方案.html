本次评审最关键的发现

信号标记（金叉/死叉、顶背离）在 SnStick 里几乎零成本落地——EChartsCandlestick 已有 markers（ChartMarker：buy/sell/neutral，含 above/color 扩展）与 priceLines 两个现成 Props，信号检测只需产出 ChartMarker[]，无需动渲染层。这是「伪得更彻底」性价比最高的一项。

二、补全 A：指标库扩展（并入 P0）

已核对 SnStick 后端 indicators/pipeline.py：现有 MA / EMA(5-60) / MACD / RSI(6,14,24 Wilder) / KDJ / BOLL，没有 OBV 副图与 CCI（obv_trend_20d 是因子库的有界趋势因子，不是 OBV 能量潮序列）。参考实现的 OBV/CCI 均为前端计算——与方案「前端指标库」的定位一致，直接在 chart/indicators.ts 扩展即可，纯函数 + 单测，无后端改动。

三、补全 B：信号标记层（并入 P0）

参考实现的两类信号直接映射到现有 ChartMarker 基础设施，渲染层零改动，只需要一个纯函数检测器 + pane 装配处把信号 merge 进 markers。

信号 1

MA5 × MA10 金叉 / 死叉

逐 bar 比较：prev(ma5)≤prev(ma10) 且 cur(ma5)>cur(ma10) → 金叉；反向 → 死叉。金叉映射 ChartMarker(kind: 'buy')，死叉映射 'sell'。参考实现只保留最近 12 个，我们按「可见窗口内全部 + 最近 N 兜底」策略，避免长历史标记过密。

信号 2

RSI 顶背离徽章

价格创窗口新高 + RSI(14) 未同步新高 → 顶部标注徽章（above: true，紫色 color 覆盖）。参考实现用自定义 series 画徽章；ECharts 用 markPoint/markers 即可。可对称扩展底背离。

信号检测器（新增 chart/signals.ts，纯函数）

export interface ChartSignal extends ChartMarker { _sig: 'ma-cross' | 'rsi-divergence' }

export function detectSignals(
  bars: OHLC[],
  opts: { maCross: boolean; rsiDivergence: boolean; window?: number }
): ChartSignal[]
// ma-cross:    遍历 i∈[1,n)，ma5/ma10 前后值比较 → buy/sell marker
// rsi-divergence: 滚动窗口 w 内 close 创新高但 rsi_14 低于窗口内 rsi 峰值
//                → neutral marker (above: true, label: '背离', color: '#7C3AED')
// 装配点: ChartPane 中 [...markers, ...detectSignals(data, paneCfg.signals)]
  • 信号开关进 PaneConfig（signals: { maCross, rsiDivergence }），默认关（TV 也是按需开启）。
  • 对象树（P2）把信号作为一类对象列出，可整体显隐。
  • 实时接入后（P3）：增量 bar 只需检测最后两根，不全量重扫。

四、补全 C：时间范围快捷栏（并入 P0）

TV 底部与参考实现底栏同款的「可见范围快捷选择」：1天 / 5天 / 1月 / 3月 / 6月 / YTD / 1年 / 5年 / 全部。落在 ChartTopbar 周期组右侧（Pill 组样式一致），实现走既有 dataZoom 通道：

const RANGES: { key: string; label: string; bars?: number | 'all' | 'ytd' }[] = [
  { key: '1d',  label: '1天', bars: 240 },   // 分钟周期: 1 交易日根数; 日K: 1 根
  { key: '5d',  label: '5天', bars: 5 },     // bars 按 pane 周期换算根数
  { key: '1m',  label: '1月', bars: 22 },
  { key: '3m',  label: '3月', bars: 66 }, { key: '6m', label: '6月', bars: 132 },
  { key: 'ytd', label: 'YTD', bars: 'ytd' },  // 年初至今年根数, 按交易日历换算
  { key: '1y',  label: '1年', bars: 250 }, { key: '5y', label: '5年', bars: 1250 },
  { key: 'all', label: '全部', bars: 'all' },
]
// 选中 → 换算该周期根数 → chart.dispatchAction({ type: 'dataZoom', start, end })
// 分钟周期范围按「交易日 × 每日根数」换算 (1d=1 交易日, 1m=22 交易日 …)
  • 与既有 visibleBars prop 的关系：范围栏是一次性 dispatch，用户手动缩放后高亮自动清除（回到「自定义」态）。
  • 联动开启时范围切换同样广播时间区间（复用缩放联动算法，t0/t1 由范围锚点得出）。
  • 分屏 pane 各自独立（与周期同理，不做全局范围联动，避免跨周期换算歧义）。

五、补全 D：涨跌停价格线（并入 P1）

参考文档将涨跌停价列为 P2 数据项；SnStick 已有涨停梯队页面（LimitUpLadder），涨跌停规则计算现成可复用。图表工作台只需在主图挂两条水平价格线：priceLines prop 直接可用（涨停红 / 跌停绿，dashed），开关进 PaneConfig，默认开。

  • 规则：主板 ±10%、创业板/科创板 ±20%、ST ±5%、北交所 ±30%——按 symbol 前缀 + 名称后缀判断，与后端涨停判定口径对齐。
  • 仅日 K 与「当日」分钟周期显示（历史日期的涨停线无意义）。
  • 对象树中可显隐该组价格线。

方案 P3 实时已有框架（useQuoteStream + mergeLatestKlineRow）。参考文档的 WS 协议语义可完整映射到 SSE 通道，补三点协议细节：

参考消息语义SnStick 落地
kline-update + isFinal未走完的最后一根 K 随 tick 演进，走完固化不再变SSE tick 合并进「当前周期桶」：分钟桶未收盘前反复重写最后一根，收盘边界（10:30/11:30/13:15…按周期对齐）固化
indicator-update指标增量只推最新值前端只重算最后一根指标（enrichChartIndicators 增量版），不全量重扫
